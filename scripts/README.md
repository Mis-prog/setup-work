# setup.sh — быстрый старт

Один файл POSIX sh настраивает рабочее место в закрытом контуре:

1. корпоративные PyPI и npm;
2. агенты из внутренних репозиториев Bitbucket (их собственный `setup.sh`);
3. на машине с GPU — llama.cpp и/или vLLM, модели из HDFS/NFS/HTTPS и запуск модели.

Не нужны Python, остальной репозиторий, sudo и правки `~/.bashrc`. Нужны `sh`, `git`,
`bash`, `awk`, `curl`; Node.js и npm уже есть на машине; для моделей — `unzip` и клиент
`hdfs` (с билетом `kinit`, если источники в HDFS).

## 1. Положить скрипт

Каталог, где лежит `setup.sh`, становится **основным**: в нём будут реестры, агенты и
`env.sh`. Удобно держать его на постоянном томе, например на NFS:

```bash
mkdir -p ~/nfs/setup-work
cp setup.sh ~/nfs/setup-work/
cd ~/nfs/setup-work
```

Другой каталог можно задать переменной `SETUP_WORK_HOME`.

## 2. Заполнить блок НАСТРОЙКИ

Откройте `setup.sh` и замените все `CHANGE-ME` в блоке `==== НАСТРОЙКИ ====`:

| Что | Где |
|---|---|
| Адрес PyPI и путь к файлу с токеном | `PYPI_INDEX`, `PYPI_AUTH_FILE` |
| Адрес npm и путь к файлу с токеном | `NPM_REGISTRY`, `NPM_AUTH_FILE` |
| Агенты: `имя  репозиторий  ветка/тег/коммит` | `AGENTS` |
| Источники движков | `LLAMA_CPP_URI`, `VLLM_URI` |
| Модели: `имя  источник  [формат]` | `MODELS` |
| Адрес запуска модели | `SERVE_HOST`, `SERVE_PORT` (по умолчанию 127.0.0.1:30000) |

Ненужный шаг отключается пустым значением (например, `VLLM_URI=''`).
В настройках указывается **путь к файлу** с токеном, а не сам токен. Если файла нет,
скрипт спросит токен, проверит его в реестре и сохранит в этот файл (права 600).

## 3. Проверить план

```bash
sh setup.sh --dry-run
```

Ничего не скачивается и не меняется: печатаются шаги и вопросы, которые будут заданы.

## 4. Запустить

```bash
sh setup.sh
```

Скрипт идёт по шагам и задаёт вопросы; ответ «нет» пропускает только этот шаг.

- **Реестры** — если pip/npm уже настроены на тот же адрес, вопросов нет.
- **Агенты** — у новых спрашивается установка, потом вход в Git и вопросы самого
  `setup.sh` агента. У установленных проверяются обновления на Bitbucket: показываются
  новые коммиты и задаётся вопрос, обновлять ли. `setup.sh` установленного агента
  выполняется при каждом запуске. Сломанную установку скрипт предложит переустановить.
- **Локальная модель** — только если `nvidia-smi` видит GPU. Предлагаются движки и модели
  под них: GGUF — для llama.cpp, HF-каталоги — для vLLM. vLLM предлагается только на
  GPU sm80 и новее (A100, H100…); на более старых — только llama.cpp.
  В конце скрипт спрашивает, запустить ли модель, и **ждёт, пока сервер ответит**
  на `/health`. Затем печатает адрес API: `http://127.0.0.1:30000/v1`.

## 5. Подключить окружение

В каждом новом терминале:

```bash
. ~/nfs/setup-work/env.sh
```

После этого доступны команды агентов, `llama-server`/`vllm` и корпоративные pip/npm.
Чтобы не делать это вручную, добавьте эту строку в свой `~/.bashrc` (скрипт сам
профили не меняет).

## Частые варианты

```bash
sh setup.sh --yes                          # на всё ответить «да»
sh setup.sh --agents=opencode,pi           # только эти агенты, без вопросов о них
sh setup.sh --no-agents --serve=qwen3.6-27b-q4   # только модель и сразу запустить
sh setup.sh --no-updates                   # не ходить на Bitbucket за обновлениями
sh setup.sh --reinstall=opencode           # переустановить агента начисто (config сохраняется)
sh setup.sh --no-local                     # без локальной модели
sh setup.sh --help                         # все параметры
```

Без терминала (CI, `nohup`) ответ на вопросы — «нет»; задайте ответы флагами или `--yes`.

## Где что лежит

| Путь | Что |
|---|---|
| `<основной каталог>/env.sh` | окружение для новых терминалов |
| `<основной каталог>/registries/` | `pip.conf`, `npmrc` с токенами (права 600) |
| `<основной каталог>/data/harnesses/<имя>/` | агент: `src`, `bin`, `config` |
| `$TMPDIR/setup-work-<uid>/engines`, `models` | движки и модели (локальный диск, не NFS) |
| `$TMPDIR/setup-work-<uid>/server/<модель>.log` | лог запущенного сервера модели |

Остановить сервер: `kill $(cut -d' ' -f1 "$TMPDIR/setup-work-$(id -u)/server/server.pid")`.

## Если что-то пошло не так

| Сообщение | Что делать |
|---|---|
| `заполните … CHANGE-ME` | заменить заготовку в блоке НАСТРОЙКИ или запустить с `--no-registries` |
| токен отклонён (401/403) | ввести новый токен, когда скрипт спросит, или обновить файл токена |
| `в src есть изменения` | сохранить свои правки агента или согласиться на переустановку |
| `сервер завершился, не успев запуститься` | смотреть хвост лога, который напечатан выше |
| `не ответил за 1800 с` | увеличить `SERVE_TIMEOUT` для больших моделей |

Коды выхода: 0 — успех, 1 — ошибка, 2 — настройки, 3 — нет нужной команды,
4 — не поддерживается (например, HF-модель на GPU ниже sm80), 6 — не найдено,
7 — токен не принят за 3 попытки, 130 — прервано Ctrl+C.
Подробное дерево решений — в разделе про `setup.sh` в [README проекта](../README.md).
